# Implemented contracts and ownership

OpenAPI is generated by springdoc at each service's `/v3/api-docs` and `/swagger-ui/index.html` in local mode. Production requires authentication. These documents describe implemented controllers; aspirational endpoints from the original brief are not exposed as fake handlers.

## REST

All endpoints are `/api/v1`. A bearer JWT is required in production. Roles abbreviate Manager (M), Approver (A), Analyst (R), Admin (D). API-level roles are enforced independently from UI visibility.

| Method/path | Purpose | Roles | Input / validation | Success / errors |
|---|---|---|---|---|
| GET `/promotions` | Browse campaigns | M A R D | `page>=0`, `size=1..100`, optional status; createdAt descending | 200 array; 400 |
| GET `/promotions/{uuid}` | Terms, version, history | M A R D | UUID | 200 object; 404 |
| POST `/promotions` | Create draft | M D | Create schema below; existing published rule UUID | 201; 400 invalid DTO; 422 invalid terms; 409 code conflict; 503 downstream |
| POST `/promotions/{uuid}/submit` | Draft to pending | M D | `{version: integer>=0}` | 200; 409 stale/transition |
| POST `/promotions/{uuid}/approve` | Approve independently | A D | version; creator differs | 200; 403 role; 422 self-approval; 409 |
| POST `/promotions/{uuid}/reject` | Return to draft | A D | version | 200; 409 |
| POST `/promotions/{uuid}/activate` | Activate in validity | M D | version | 200; 422 outside validity; 409 |
| POST `/promotions/{uuid}/schedule` | Schedule future start | M D | version | 200; 422 invalid schedule; 409 |
| POST `/promotions/{uuid}/pause`, `/retire`, `/expire` | Lifecycle transitions | M D | version; expiry requires end reached | 200; 409; 422 |
| GET `/rules`, `/rules/{uuid}` | Published immutable versions | M A R D | UUID for detail | 200; 404 |
| POST `/rules` | Validate and publish first immutable version | M D | `{name,expression}`; name <=120; bounded AST | 201; 400 |
| POST `/rules/validate` | Validate typed expression | M D | `{name,expression}` | 200 validated decision; 400 |
| POST `/rules/simulate` | Evaluate supplied expression | M D | `{expression,facts}` | 200 `{eligible,reasons}`; 400 |
| POST `/rules/{uuid}/evaluate` | Evaluate exact stored version | M A R D | facts map with whitelisted customer attributes | 200 decision; 404; 400 |
| GET `/customers`, `/customers/{opaqueId}` | Synthetic/customer attributes | M A R D | page/size as above | 200; 400; 404 |
| GET `/customers/{id}/eligible-promotions` | Active offer preview | M A R D | customer reference | 200 `{promotion,customer,eligible,reasons}[]`; 503 |
| GET `/eligibility/{customerId}/{promotionUUID}` | Single eligibility snapshot | M A R D | identifiers | 200 snapshot; 503 |
| GET `/redemptions`, `/redemptions/{uuid}` | History | M A R D | page/size; redeemedAt descending | 200; 404 |
| POST `/redemptions` | Redeem | M D | header `Idempotency-Key: [A-Za-z0-9_-]{8,128}`, body `{promotionId,customerId}` | 201 including duplicate original result; 400; 422 ineligible/expired/currency; 409 cap/key conflicts |
| POST `/redemptions/{uuid}/cancel` | Compensation | M D | UUID; repeatable | 200 including repeats; 404 |

Every route has 401 for missing/invalid production authentication and 403 for role mismatch. Gateway limit is 120 requests/principal/minute per replica; body limit 64 KiB after deserialization. Enforce size/rate/headers at ingress before allocation for production. Query handling uses zero-based page and maximum 100 rows; list responses currently return arrays without total-page metadata. UI live overview therefore uses the first page only; full cursor pagination is a release gate.

Create example:

```json
{"code":"FAMILY25","name":"Family connections","description":"25 percent for eligible postpaid customers","discountType":"PERCENTAGE","discountValue":25,"currency":"SGD","startAt":"2026-10-11T00:00:00Z","endAt":"2026-11-11T00:00:00Z","totalRedemptionLimit":1000,"perCustomerLimit":1,"budgetLimit":20000,"ruleVersionId":"38b9d8cf-a6bf-4bfc-b44a-4e466bd87d06","segment":"Postpaid","channel":"My Singtel"}
```

Rule example:

```json
{"name":"Postpaid Singapore","expression":{"op":"AND","children":[{"op":"EQ","field":"segment","value":"Postpaid"},{"op":"GTE","field":"spend","value":"40"},{"op":"NOT","children":[{"op":"EQ","field":"excluded","value":"true"}]}]}}
```

Expected business errors use RFC 9457 Problem Details with `type`, `title`, `status`, `detail`, `code`, `correlationId`. Spring Security authentication failures use its standard challenge response at present; uniform security Problem Details and field-level validation details need completion.

## Persistence and boundaries

Each deployable contains `db/migration/V1__service_schema.sql`. PostgreSQL production profile uses Flyway then `ddl-auto=validate`. Local H2 uses `ddl-auto=update` and no Flyway. Never run local schema updates against production.

| Owner | Tables / invariants |
|---|---|
| Promotion | promotions; UUID PK, unique code, state/date index, JPA optimistic version, JSON audit timeline. Terms immutable in first slice |
| Rules | rule_versions; UUID PK; immutable JSON snapshot, checksum, actor and publication timestamp; no update endpoint |
| Customer | customers; opaque synthetic PK, segment index; minimal segment/plan/channel/region/spend/status/consent attributes |
| Redemption | campaign_ledgers; UUID campaign reference (no cross-service FK), nonnegative spent/count; redemptions FK to owned ledger, actor+key unique, customer/campaign/status and date indexes |
| Each service | outbox_events; UUID PK, pending-publication index, created/published timestamps, attempts |

Approval history and audit are embedded in the campaign timeline in this slice. A production schema should normalize approval/administrative audit tables with an append-only actor/trace/version envelope. Reservations, normalized immutable redemption transition history, consumer-deduplication, notification-delivery and analytics projection tables belong to the next phase; do not add dormant tables as a substitute for business logic.

Proposed retention (requires policy approval): idempotency entries for the longest caller retry window (at least 30 days proposed), financial transactions per organizational/legal policy, published rule versions as long as any campaign references them, delivered outbox 30 days after consumers' replay horizon, operational logs 30 days with PII minimization. No purge job is implemented; reconcile retention with incident replay, deletion obligations and accounting rules before introducing one.

## Events

All business events use topic `promotion.events.v1` and an envelope governed by [event schema](event-envelope.schema.json). Kafka key is aggregate UUID; ordering is per partition/key, not globally. New optional data fields are backward compatible. Removing/renaming fields or changing semantics needs a new schema version/topic and consumer migration. JSON Schema is checked in for governance; a registry and compatibility CI gate remain required.

```json
{"eventId":"7f4a2d08-6184-44d3-a7c6-d8bed952b74b","schemaVersion":1,"type":"redemption.completed","aggregateId":"b5de7480-99c6-46e1-a2e3-c3fa56c8cf09","occurredAt":"2026-10-11T04:00:00Z","data":{"redemptionId":"b5de7480-99c6-46e1-a2e3-c3fa56c8cf09","promotionId":"38b9d8cf-a6bf-4bfc-b44a-4e466bd87d06","discountAmount":12.50,"currency":"SGD"}}
```

Consumers must store `(consumer_name,event_id)` under a unique key in the same transaction as their local projection update; retry duplicate events as no-ops. Deliveries need a unique provider-operation key, consent recheck, bounded exponential retry and a dead-letter workflow. These are target contracts, not implemented consumers.
